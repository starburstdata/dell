    Command line interface#

    Dell Data Analytics Engine, powered by Starburst Enterprise platform (SEP) provides a terminal-based interactive shell for running Dell Data Processing Engine queries.

    Requirements#

    The Dell Data Processing Engine CLI has the following requirements:

    • Java 22

    • Must be able to open a web browser for logging in to your IdP

    Installation#

    Download and extract the .tar.gz file from the downloads archive. In the terminal, navigate to the bin directory and execute the dell-data-processing-engine.sh script with the version command to see the version of the CLI:

    ./dell-data-processing-engine version

    Windows users must run the .bat script located in the same directory.

    Running the CLI#

    You can accomplish many tasks with the CLI using the Dell Data Processing Engine API endpoints, such as managing your profiles, submitting batch jobs, and configuring resource pools. You can view supported commands, or run the CLI with --help or -h to see all available options:

    Connecting to HMS with Kerberos authentication#

    When submitting a Spark job while using Kerberos authentication with Hive Metastore, there are some additional configuration steps required:

    1. Upload a keytab and Kerberos config file using the CLI, then activate each upload:

      ./dell-data-processing-engine upload add -n kerberos-config /path/to/krb5.conf
  ./dell-data-processing-engine upload activate name=kerberos-config
  ./dell-data-processing-engine upload add -n kerberos-keytab /path/to/hive.keytab
  ./dell-data-processing-engine upload activate name=kerberos-keytab

    1. Run the following Python script to authenticate a PySpark application using Kerberos credentials from a keytab file:

    import sys
from pyspark.sql import SparkSession

def loginUserFromKeytab():
    sc = spark.sparkContext
    hadoop_conf = sc._jsc.hadoopConfiguration()

    keytab = hadoop_conf.get("spark.yarn.keytab")
    principal = hadoop_conf.get("spark.yarn.principal")

    ugi_class = sc._jvm.org.apache.hadoop.security.UserGroupInformation
    ugi_class.loginUserFromKeytab(principal, keytab)

spark = SparkSession.builder \
    .appName("FixedKeyMapping") \
    .enableHiveSupport() \
    .getOrCreate()

loginUserFromKeytab()

spark.sql("SHOW DATABASES").show()

    The script creates a Spark session with Hive support enabled, and then retrieves the keytab file path and principal name from the Spark configuration and uses them to complete Kerberos authentication. Once authenticated, the script runs the spark.sql("SHOW DATABASES").show() command as an example to list available databases.

    1. Run the following example job create command, replacing the keytab file name, principal, resource pool, and the Thrift URL in the command to match your environment. This creates the job but does not start it:

    ./dell-data-processing-engine job create \
--resource-pool default \
--mount name=kerberos-config:/kerberos/config \
--mount name=kerberos-keytab:/kerberos/keytab \
--conf spark.sql.catalogImplementation=hive \
--conf spark.security.credentials.hive.enabled=true \
--conf spark.hadoop.hive.metastore.use.SSL=false \
--conf spark.hadoop.hive.metastore.uris=thrift://10.0.0.92:9083 \
--conf spark.hadoop.hive.metastore.sasl.enabled=true \
--conf spark.hadoop.hive.metastore.authentication=KERBEROS \
--conf spark.hadoop.hive.metastore.kerberos.keytab.file=/opt/spark/uploads/kerberos/keytab/hive.keytab \
--conf spark.hadoop.hive.metastore.kerberos.principal=hive/hadoop-master@LABS.TERADATA.COM \
--conf spark.hadoop.spark.yarn.keytab=/opt/spark/uploads/kerberos/keytab/hive.keytab \
--conf spark.hadoop.spark.yarn.principal=hive/hadoop-master@LABS.TERADATA.COM \
--conf spark.hadoop.hadoop.security.authentication=kerberos \
--conf spark.hadoop.hadoop.security.authorization=true \
--conf spark.driver.extraJavaOptions="-Djava.security.krb5.conf=/opt/spark/uploads/kerberos/config/krb5.conf" \
--conf spark.executor.extraJavaOptions="-Djava.security.krb5.conf=/opt/spark/uploads/kerberos/config/krb5.conf" \
  path-to-the-python-file

    1. Start the job, using the job ID returned by the previous command:

    ./dell-data-processing-engine job run <job-id>

    Jobs#

    The following CLI commands manage Spark batch jobs:

    Job CLI commands#

    Command

    Description

    Options

    job

    Job management.

    job create

    Create a new job. Accepts the application resource (jar, Python file, R file, etc.) as a positional argument, followed by any application arguments. Without a schedule option, the job is created as adhoc; use --cron/--cron-timezone, --fixed-rate, or --execute-at to create a recurring or scheduled job instead. Creating a scheduled or recurring job does not enable it; use job activate to enable its schedule.

    • --name. A name for the job. If not provided, a name is generated.

    • --resource-pool. Resource pool ID or name to use. Required.

    • --instance-image-id. Instance image ID to use.

    • --jars. Comma-separated list of .jar files to include on the driver and executor classpaths.

    • --py-files. Comma-separated list of .zip, .egg, or .py files to place on the PYTHONPATH for Python apps.

    • --files. Comma-separated list of files to be placed in the working directory of each executor. File paths of these files in executors can be accessed with SparkFiles.get(fileName).

    • --archives. Comma-separated list of archives to be extracted into the working directory of each executor.

    • -c, --conf. Arbitrary Spark configuration property.

    • --env. Add environment variables to the job. Each entry must be in the form key=value.

    • --executor-memory. Memory per executor. Defaults to 1G.

    • --num-executors. Number of executors to launch. Defaults to 2.

    • --executor-cores. Number of cores used by each executor. Defaults to 1.

    • --encrypt. Enable encryption for communication between the driver and executors. Defaults to true.

    • --description. Description of the job.

    • --class. Your Java or Scala application’s main class.

    • --ttl-seconds-after-finished. TTL cleanup in seconds after the job finishes.

    • --max-retries. Maximum number of retries on failure. Must be 1 or greater.

    • --mount. Attach an upload to the job. Format: [name=<upload-name>|<upload-id>]:<mount-path>. The mount path is optional; if omitted, the upload’s default mount path is used. Can be specified multiple times.

    • --cron. CRON expression. Creates a recurring job. Mutually exclusive with --fixed-rate and --execute-at.

    • --cron-timezone. CRON time zone. Only valid with --cron.

    • --fixed-rate. Period between executions of a recurring job, such as 90s, 5m, 2h, or 3d. Mutually exclusive with --cron and --execute-at.

    • --execute-at. When to run a scheduled job, in ISO-8601 format (for example 2027-03-15T10:30:00). Mutually exclusive with --cron and --fixed-rate.

    job get

    Get details of a job.

    job list

    List jobs.

    • --id. Filter by exact job ID.

    • --name. Filter by fuzzy word similarity of the name.

    • --kind. Filter by kind (adhoc, scheduled, recurring). Can be repeated to match multiple values.

    • --status. Filter by status. Can be repeated to match multiple values.

    • --last-run-status. Filter by the status of the last run. Can be repeated to match multiple values.

    • --created-by. Filter by submitter. Can be repeated to match multiple values.

    • --resource-pool-id. Filter by resource pool ID. Can be repeated to match multiple values.

    • --created-from, --created-to. Filter by creation time range (ISO-8601 instant).

    • --last-run-from, --last-run-to. Filter by last run time range (ISO-8601 instant).

    • --next-run-from, --next-run-to. Filter by next scheduled run time range (ISO-8601 instant).

    • --sort. Sort by <field> [asc|desc], where field is one of createdAt, id, or nameSimilarity (direction defaults to asc). Sorting by nameSimilarity requires --name.

    • --columns. Display only the specified columns, in the given order.

    • --all-columns. Display every available column.

    job update

    Update an existing job. Every option is optional; an omitted option leaves the corresponding value unchanged. A job’s kind (adhoc, scheduled, recurring) cannot be changed by this command.

    • --name, --resource-pool, --instance-image-id, --description, --class, --application, --ttl-seconds-after-finished, --max-retries, --encrypt, -c/--conf, --cron, --cron-timezone, --fixed-rate, --execute-at. Same meaning as on job create.

    • --jars/--no-jars, --py-files/--no-py-files, --files/--no-files, --archives/--no-archives, --mount/--no-mounts, --args/--no-args, --env/--no-envs, -c/--conf/--no-conf. Each --no-* flag clears the corresponding list, and is mutually exclusive with its paired option.

    • Passing an empty string clears --description and --class; passing 0 clears --ttl-seconds-after-finished and --max-retries.

    job clone

    Create a new job from an existing one. Every option other than --name is optional and, when omitted, is inherited from the source job. The clone’s kind may differ from the source’s.

    • --name. A name for the cloned job. Required.

    • --adhoc. Clone as an adhoc job, dropping the source job’s schedule.

    • All other options from job create and job update, applied the same way, but inherited from the source job when omitted instead of left unchanged. When cloning to a --cron recurring job, --cron may itself be omitted to inherit the source’s cron expression (the source must already be a cron recurring job).

    job run

    Start a job.

    job activate

    Enable a scheduled or recurring job’s schedule.

    job deactivate

    Disable a scheduled or recurring job’s schedule, without removing the job.

    job terminate

    Stop a job’s current run. The job definition is not removed, and can be run again.

    • --force. Immediately terminate the job’s run without waiting for normal shutdown.

      Warning

      Using the --force option can result in loss of final logs and events.

    job delete

    Delete a job definition.

    Seal an upload. No further items can be added or removed.

    info

    Get the details of an upload.

    add

    Upload a set of files.

    • -n, --name. The name of this upload. If an upload with the same name already exists and has not yet completed, this appends to the existing upload. Required.

    • -d, --description. The description of this upload.

    • -m, --mapping. Maps source file names to destination paths using patter

      Wildcards:

      * - Any characters (except path separators)
      ** - Any characters (including path separators)
      ? - Single character
      {name} - Named capture group

      Without wildcards, the mapping is treated as a literal match.

      Examples:

      a=b - Literal: a -> b
      *.txt=backup/*.txt - foo.txt -> backup/foo.txt
      {name}-{ver}.jar=lib/{name}/{ver}.jar - app-1.0.jar -> lib/app/1.0.jar

    • --show-mappings-only. Does not perform the upload, only shows the file mappings that would be applied.

    • --retain-paths. Retain relative paths of uploaded files. For example, if uploading files from /mycomputer/users/work/data/local and the working directory is /mycomputer/users/work/, the uploaded files retain the data/local/ path. Use --mappings to override this behavior.

    Examples#

    The following sections show you how to use various Dell Data Processing Engine CLI commands.

    Login to CLI#

    Logging into the CLI requires authorizing with your IdP. Enter the login command to login with the default role:

    ./dell-data-processing-engine login

    Login with the admin role:

    ./dell-data-processing-engine login --role admin

    Login with the analyst role:

    ./dell-data-processing-engine login --role analyst

    The login command opens a new tab in your browser requiring you to enter your credentials. Upon logging in, an access token and encrypted value is generated and written to your local configuration file for later use.

    Create a recurring batch job on a schedule#

    Add --cron to create a recurring job instead. The following runs every hour at minute 0:

    ./dell-data-processing-engine job create --class org.apache.spark.examples.SparkPi --resource-pool default --cron "0 * * * *" "local:///opt/spark/examples/jars/spark-examples_2.12-3.5.7.jar"

    To create a job that runs every day at 12:00 PM:

    ./dell-data-processing-engine job create --class org.apache.spark.examples.SparkPi --resource-pool default --cron "0 12 * * *" "local:///opt/spark/examples/jars/spark-examples_2.12-3.5.7.jar"

    The timezone is UTC by default. Change it with --cron-timezone, using a valid timezone name. The following runs at 12:00 PM EST:

    ./dell-data-processing-engine job create --class org.apache.spark.examples.SparkPi --resource-pool default --cron-timezone "EST" --cron "0 12 * * *" "local:///opt/spark/examples/jars/spark-examples_2.12-3.5.7.jar"

    Creating a recurring job does not enable its schedule. Activate it to start running:

    ./dell-data-processing-engine job activate <job-id>

    To pause the schedule without deleting the job, use job deactivate <job-id>.

    Configure resource pools#

    The following example shows two resource pools being set, one named default with a minimum number of cores set to 1, and another named large with a minimum number of cores set to 3 and a maximum number of cores set to 8:

    ./dell-data-processing-engine admin resource-pools set --name default --min-cores 1 --name large --min-cores 3 --max-cores 8

    Note that in this example, the default resource pool does not explicitly set a maximum number of cores with the --max-cores option. The default resource pool instead uses the default value for --max-cores which is 1.

    You can use the get command to return a list of your resource pools and their configuration:

    ./dell-data-processing-engine admin resource-pools get
